# 🏗️ معمارية خط البيانات (Data Pipeline Architecture)

يعتمد هذا المشروع على معمارية هجينة (Hybrid ELT) مصممة لمعالجة البيانات الضخمة بمرونة وموثوقية، مع ضمان عدم فقدان البيانات الأصلية وتتبع كافة التعديلات.

---

## 1. مراحل المعالجة الأساسية (Processing Stages)

تم تصميم خط الأنابيب ليمر بسبع مراحل متسلسلة لضمان جودة واتساق البيانات:

* **اكتشاف الملف:** قراءة المسار والحجم وإنشاء معرف فريد `run_id` للعملية.
* **اختيار المحرك:** الفحص التلقائي لحجم الملف وتوجيهه؛ للملفات الصغيرة يُستخدم `Python Batch`، وللملفات التي تتجاوز الحد يُستخدم `PySpark`.
* **التحميل الخام (Raw Load):** تحميل جميع السجلات إلى مجموعة `orders_raw` كما وصلت، دون أي فلترة جودة، للحفاظ على نسخة أصلية.
* **التحويل والجودة (Transform & Quality):** تطبيع الأنواع والصيغ وتطبيق قواعد التصحيح والتحقق الآلية.
* **التصنيف (Classification):** تصنيف كل سجل بدقة إلى صالح (Valid)، مصحح (Corrected)، أو معزول (Quarantined).
* **التحميل النهائي (Final Load):** استخدام `Upsert` لكتابة السجلات السليمة والمصححة في `orders_validated`، وكتابة السجلات غير القابلة للتصحيح في `orders_quarantine`.
* **التحقق (Idempotency Check):** ضمان عدم زيادة السجلات المكررة عند إعادة تشغيل نفس المدخل، وعدم إنشاء Duplicate records.

---

## 2. التدفق المنطقي (Logical Data Flow)

يوضح المخطط التالي مسار البيانات من المصدر إلى قواعد البيانات النهائية:

    Provided Dirty CSV 
           │
           ▼
    File Router: size <= 200MB ?
           │
       ┌───┴───┐
       ▼       ▼
    Python   PySpark
       │       │
       └───┬───┘
           ▼
      orders_raw (ELT Raw Load)
           │
           ▼
    Cleaning + Validation (8+ Rules)
           │
           ▼
    Classification (Valid / Corrected / Quarantined)
           │
       ┌───┴───────────────┐
       ▼                   ▼
    Idempotent Upsert    Insert
       │                   │
       ▼                   ▼
    orders_validated   orders_quarantine

---

## 3. القرار المعماري: الموجه التلقائي (File Router)

تم تحديد الحد الفاصل لحجم الملف بـ `200 MB`. 
* **المبرر:** الملفات التي يقل حجمها عن 200 ميجابايت تُعالج بكفاءة وموثوقية عبر `Python Batch` بصورة Streaming دون استهلاك زائد للذاكرة أو الحاجة لبناء Cluster. أما الملفات الضخمة التي تتجاوز هذا الحد فتتطلب توزيع المهام واستخدام DataFrame API عبر `PySpark` للقراءة والمعالجة والكتابة بالتوازي لضمان سرعة الإنجاز.
